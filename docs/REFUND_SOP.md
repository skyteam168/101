# 退款操作规范（P1）

系统已支持「正式退款」：写入 `order_refunds`、扣减 `paidAmount`、更新 `paymentStatus`，并记审计 `order.refund`。报表营业额按净实收（`paidAmount`）统计，支付方式汇总会减去退款。

退款成功后自动向前台打印机投递 **退款小票**（`PrintJobKind.refund` / 模板 `refund`）；订单详情可「打印退款小票」重打。

权限：`order:refund`（seed 默认给店长 / 超管；收银不含）。

## 堂食

| 场景 | 做法 | 系统操作 |
| --- | --- | --- |
| 未结账点错菜 | 收银退菜 | 订单详情 / 收银台 → 退菜（需 `order:void-item`） |
| 整桌不要了 | 取消订单 | 取消（需 `order:cancel`），桌台回空闲 |
| 已结账后发现错账（要改单再结） | 反结账 | 「反结账」（`order:checkout`），清除支付并恢复用餐中。**已有退款记录时禁止反结账** |
| 已结账且顾客要退钱（全额/部分） | 正式退款 | 订单详情 →「退款」：金额、退回方式、原因（`order:refund`）；自动打退款小票 |

## 外卖

| 场景 | 做法 | 系统操作 |
| --- | --- | --- |
| 未接单 / 制作前 | 拒单或取消 | 外卖看板拒单/取消 |
| 配送中协商取消 | 与顾客确认后取消 | 取消订单；若已收转账则线下退回后，完成单可再走正式退款（若状态已 completed） |
| 已完成（completed）且已标已支付 | 正式退款 | 看板「退款」进订单详情，或订单详情直接退款；自动打退款小票 |

## 退款规则摘要

- 可退：`status` 为 `paid`（堂食）或 `completed`（外卖），且 `paymentStatus` 为 `paid` / `partial`，剩余 `paidAmount > 0`
- 金额：1 … 剩余已付；支持多次部分退
- 全额退完后：`paymentStatus = refunded`，`paidAmount = 0`；订单 `status` **不变**
- 退回方式：现金当面 / 转账 / 卡 / MoMo / VNPay（登记实际退给顾客的渠道；原路退网关对接仍属后续）
- 小票：退款金额、方式、原因、原账单、累计已退、剩余已付；前台网口 agent 或浏览器 USB 打印台

## 交班核对

1. 报表「支付方式」已含退款冲减，与钱箱/银行到账核对  
2. 审计日志筛选 `order.refund` 复核大额/争议单  
3. 保留聊天记录 / 退款小票 / 照片备查
